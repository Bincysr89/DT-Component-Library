Dirham Symbol

The UAE Dirham glyph, as the application ships it — an inline <svg> sized in em and painted with currentColor, so it takes the size and colour of the text beside it with no per-use styling. Every AED amount in the product carries it.

Dirham Symbol 1em Symbol
Inherits the surrounding colour
Dark (#0E1B3D)
Light (#FFFFFF)
Grey (#F5F6FA)
Download dirham-symbol.svg Standalone file — viewBox="0 0 20 17", fill="currentColor". Drop it into an icon set, or paste the path into a component.
Inherits the surrounding size and weight
1,250.00 1,250.00 1,250.00 1,250.00
HTML
<!-- 1. Define the glyph once, anywhere in the document (it renders nothing) -->
<svg xmlns="http://www.w3.org/2000/svg" style="display:none" aria-hidden="true">
  <symbol id="dirham-glyph" viewBox="0 0 20 17">
    <path d="M1.766 0.0195402C1.774 0.0312644 …" />
  </symbol>
</svg>

<!-- 2. Reference it wherever an amount appears -->
<svg data-dirham role="img" aria-label="Dirham"><use href="#dirham-glyph" /></svg>

<!-- With an amount — the pairing to use wherever you would have written "AED 1,250" -->
<span data-amount>
  <svg data-dirham role="img" aria-label="Dirham"><use href="#dirham-glyph" /></svg>
  1,250.00
</span>

<!-- In a table cell, a heading, a button — no size or colour is ever set on the
     glyph itself; it follows the text it sits next to. -->
<td><span data-amount><svg data-dirham><use href="#dirham-glyph"/></svg>4,800.00</span></td>
<h3><span data-amount><svg data-dirham><use href="#dirham-glyph"/></svg>12,000.00</span></h3>

<!-- A component framework can inline the <path> instead of using <symbol>, which
     is what the application's Dh component does — the CSS below is identical
     either way. -->
CSS
/* Two rules are the whole component */
[data-dirham] {
  display: inline-block;
  width: 1em; height: 1em;  /* follows the text size   */
  fill: currentColor;  /* follows the text colour */
  vertical-align: -.12em;  /* sits on the baseline    */
  flex-shrink: 0;
}

[data-amount] {
  display: inline-flex;
  align-items: baseline;
  gap: 4px;
}

/* Nothing else is needed: the glyph is black on white, white on navy and blue
   inside a link, because it never sets a colour of its own. */

Toggle

2 states — Off and On. Click either one: they are real checkboxes carrying role="switch". 48×28 track: #E2EBF9 off, brand blue on; the 22px white thumb slides right.

HTML
<!-- Off -->
<label data-switch>
  <input type="checkbox" role="switch">
  <span>Disabled</span>
</label>

<!-- On -->
<label data-switch>
  <input type="checkbox" role="switch" checked>
  <span>Enabled</span>
</label>

<!-- role="switch" makes a screen reader say "on / off" instead of
     "checked / not checked". Everything else is a plain checkbox:
     it toggles with Space, submits with a form, and needs no JavaScript. -->
CSS
label[data-switch] { display: inline-flex; align-items: center; gap: 10px; cursor: pointer; }

/* Track — the input itself */
[data-switch] > input {
  appearance: none; -webkit-appearance: none; margin: 0; position: relative; flex-shrink: 0;
  width: 44px; height: 24px; border-radius: 12px;
  background: #fff; border: 2px solid #1360D2;
  box-sizing: border-box; cursor: pointer; transition: background .15s;
}

/* Thumb — a pseudo-element, so the track needs no child */
[data-switch] > input::after {
  content: ""; position: absolute; top: 2px; left: 2px;
  width: 16px; height: 16px; border-radius: 50%;
  background: #1360D2; transition: left .15s, background .15s;
}

/* On — driven by :checked, not by a class toggled in JavaScript */
[data-switch] > input:checked { background: #1360D2; }
[data-switch] > input:checked::after { left: 22px; background: #fff; }

/* Label follows the control's state */
[data-switch] > span { font-size: 14px; color: #696F83; }

Attribute Values Required Purpose

State Expressed by CSS hook Accessibility note

JavaScript
// Wire up every [data-view-toggle] on the page.
// aria-pressed is both the visual hook and the accessible state —
// no extra "active" class is needed.
document.querySelectorAll('[data-view-toggle]').forEach(function(toggle) {
  toggle.addEventListener('click', function(e) {
    const btn = e.target.closest('button');
    if (!btn) return;
    toggle.querySelectorAll('button').forEach(function(b) {
      b.setAttribute('aria-pressed', b === btn ? 'true' : 'false');
    });
  });
});

Listing Page Interaction Reference

Interaction rules and design decisions that govern how listing / search pages behave across Dubai Trade modules.

Basic Search
User must enter the complete search value and press a button or icon to trigger results in the table. Component: Search field with trailing button
Live Search Condition

If the system can filter the table as the user types (without requiring a button press), use a simple search field without a highlighted or filled search button — a plain input with a non-interactive search icon is sufficient. This avoids implying that an explicit submission is required.

Reference — with trailing button (explicit submit)
Reference — simple field (live / real-time search)
Dropdown Fields
Support single-select or multi-select based on business requirement.
  • Multi-select dropdowns use checkboxes alongside available values.
  • A separate "Search" or "Save" button is not required.
  • Selections are applied automatically upon selection.
Reference
Status Dropdown
Placed alongside the Basic Search. May directly populate relevant records based on the default date range defined under the "Status As On" section, subject to system performance and technical feasibility.
Status As On — Modify & Calendar Icon
The "Modify" text and the calendar icon next to "Status As On" act as a single clickable control. Either interaction can be used based on system performance and business requirement:
  • Option 1 — Date range selector: Opens an inline date range picker so the user can change the date range applied to the table directly.
  • Option 2 — Advanced Filters card: If a standalone date range picker is not technically feasible, clicking either control opens the Advanced Filters card instead, where the date range fields are available.
Reference — Status As On control
Drafts Toggle
For modules where drafts are applicable, provide a Drafts toggle.
  • When Drafts is enabled, display the relevant table, search, and filters.
  • The Status filter is disabled / greyed out when viewing drafts.
  • Switching back from Drafts to regular records resets all filters to avoid carrying over irrelevant criteria.
Decision Guidance
  • Use a toggle when the Drafts table has different columns or interactions compared to the regular records view — keep it as a separate access point via the toggle.
  • Use a Status filter value when Drafts share the same table columns and interactions as regular records — in this case, "Draft" can simply be one of the options in the Status dropdown.
Reference — Draft toggle ON, Status greyed out
Advanced Filters
  • When the Advanced Filters card is expanded, hide or grey out the basic search, status dropdown, and status-related controls to reduce confusion.
  • Once filters are applied, display the selected criteria as tags below the card so users can identify active filters even when the card is collapsed.
  • Each tab (All Records, ePayment, Drafts, etc.) maintains its own independent set of filters. Filters applied in one tab do not carry over to another.
Reference — Expanded: basic search & status greyed out
Help / Knowledge Hub
The "Need help" action opens the relevant Knowledge Hub page in a new window. URL to be provided by the Dubai Trade team.
Column Rearrangement Preferences
Where technically feasible, the user's column rearrangement preferences should be saved against their user login / profile — retained across sessions and devices. Reference: Column customisation in JIRA
Reference — Columns button in toolbar
Card View & List View
Users can toggle between List View and Card View for the data table. This supports responsive screens where a full-width table may not be practical.
  • List View — displays the standard data table with columns, sortable headers, and row actions.
  • Card View — displays each record as a card in a responsive grid, showing the most important fields. Better suited for smaller screens and record browsing.
Toggle Control

Place the card/list toggle in the toolbar alongside the search and filter controls. Both icons should be visible at all times — the active view is highlighted.
